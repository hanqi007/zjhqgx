# zjhqgx — 安全公告通道

这个仓库只有一个用途：**共同漏洞 / 紧急重大安全补丁的公告通道**。

它**不是常规发版渠道**——日常版本更新走各自项目仓库的 `package.json`，只有出现「多个插件共有的漏洞」或「必须尽快打上的重大安全补丁」时，这里才会多一条公告。

## 为什么单独放一个仓库

- 漏洞往往横跨多个插件，逐个仓库发公告容易漏
- 公告要能被**还没升级的旧版本**读到
- 补丁包要能在一个地方取到

## 公告格式

文件：`security.json`，schema 2。

```json
{
  "schema": 2,
  "updated": "2026-10-30",
  "advisories": [
    {
      "id": "ZJHQGX-2026-007",
      "plugin": "dsh-cjgl",
      "severity": "low",
      "affected": "<3.6.12",
      "fixed": "3.6.12",
      "title": "运行环境兼容性自检缺失",
      "description": "…",
      "publishedAt": "2026-10-30"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `plugin` | 受影响插件的包名，必须与 `package.json` 的 `name` 一致 |
| `affected` | 版本区间，支持 `<` `<=` `>` `>=` `=` |
| `fixed` | 修复版本；插件会去 `dist/<plugin>-<fixed>.tgz` 取包 |
| `severity` | `low` / `medium` / `high` / `critical` |
| `description` | 说清楚**为什么**要打这个补丁，用户能在设置页看到 |

## 强制静默更新

装了本通道的插件（`dsh-cjgl`、`hdd-console-boot`、`dsh-gd`）按这个流程走：

1. 检查更新时，**先读本仓库的 `security.json`**
2. 命中当前版本（`plugin` 对上、`fixed` 高于当前、`affected` 覆盖当前）时：
   - **不弹窗、不询问**
   - 后台下载 `dist/<plugin>-<fixed>.tgz`
   - 解压覆盖 `node_modules/<plugin>`
   - 改写 profile 的 `dependencies` 指向新包
   - 记下「已自动应用」，设置页可见
3. 失败也不打扰用户，只在设置页留一行原因，**24 小时后重试**

### 为什么强制

安全补丁的价值在于「用户还没来得及反应就已经装上了」。弹窗等于把决定权交给可能不看公告的人。

### 代价

**修复版本本身有问题时，用户不会收到询问。** 所以发 `fixed` 版本之前必须本地验证过——
这条通道是单向的，发出去了就收不回。

## 与其他仓库的关系

| 仓库 | 用途 |
|---|---|
| 各插件仓库（`dsh-cjgl` / `dsh-hdd` / `dsh-gd` …） | 常规发版、源码、README |
| `zjhqgx`（本仓库） | 只放安全公告与对应补丁 |

常规版本更新**不会**从这里发。

## 维护约定

- 只追加，不删除已发布的公告（历史要能追溯）
- `updated` 字段每次改动都要更新
- 新增公告后，确保对应插件的 `dist/<plugin>-<fixed>.tgz` 已经存在且可下载
- 本仓库必须**保持公开**：插件是匿名请求的，仓库私有会导致公告读不到、静默更新完全失效
